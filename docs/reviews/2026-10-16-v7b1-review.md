### MEDIUM-1: the "copies every constructor argument" test does not catch a dropped argument that is left at its default

- **Where:** backend/tests/test_identity_sizing.py:323-342, which guards backend/trading/orchestration/pipeline.py:258-275.
- **Evidence:** The test builds `original` with six arguments (pipeline.py defaults are used for `mode`). It then checks `getattr(copy, "_"+name) is getattr(original, "_"+name)` for every name in the signature.
  - An argument that the original leaves at its default looks the same in the copy even when the copy drops it, because both sides hold the same default object.
  - Mutation results, full suite (see table):
    - d2: dropping `mode=` from the copy survives.
    - d3: adding a new keyword argument `max_shares: int | None = None` that the copy forgets survives.
    - d1: turning a `None` identity factor into `NO_SCALING` inside the copy (`self._identity_multiplier or NO_SCALING`) survives. The test only copies 0.25.
- **Failure scenario:** Someone later adds a sizing-bearing argument to `ShadowPipeline` with a default, for example a per-identity share cap or a new narrowing factor. They wire it in shadow_service.py but forget `with_decision_recorder`. That is the same bug class as v7b.1.
  - Every production session then silently runs with the default, and the suite stays green.
  - The docstring (pipeline.py:264-265), the commit message and LEARNED.md all say a test ties the copy to the signature. It does so only for arguments the fixture sets to non-default values.
  - d1 is the narrower version of the same gap: a refactor of the copy can reopen the missing-row fail-open, and no test notices. Two things still hold the line there: the launch preflight `registry_problems` (shadow_service.py:211-213) and the table-equality test.
- **Fix (tests only, no production change):**
  - In the signature test, assert that every parameter of `original` differs from its default: `getattr(original, "_"+n) is not param.default`. That forces the fixture to set every argument, including `mode`, and fails the moment a new argument appears.
  - Add a runner-level case with `identity_multiplier=None` that expects `risk_blocked` / `identity_sizing_missing` (the replay helper already accepts it).

## 3. End-to-end sizes, rounding, Decimal, managed product

- **Sizes:** see the table above. Every V2 identity equals `floor(3726 × row)`.
- **Rounding:** `_whole_units` uses `ROUND_DOWN` on a positive Decimal, which is floor (risk/engine.py:31-32). Scaling is applied once, after every policy check (risk/engine.py:127-130). A result below one share becomes `size_scaled_to_zero`, never one share.
- **Decimal:** the identity row is a Decimal, checked when the module is imported and again in the constructor (identity_sizing.py:34-39, pipeline.py:216-219). The managed factor must be a finite Decimal in [0, 1]; otherwise it falls back to 1 with a CRITICAL log (pipeline.py:557-571). Their product, for example 0.25 × 0.75 = 0.1875, is exact at precision 28. Nothing in backend/ changes the Decimal context (no `getcontext`/`localcontext`).
- **The product never exceeds 1.**
  - The identity factor is in (0, 1] and the managed factor is in [0, 1].
  - A managed factor of 0 is blocked before the engine (pipeline.py:469-487).
  - `require_size_multiplier` checks the product again (risk/engine.py:89). A failure there becomes `RISK_BLOCKED` with no intent (pipeline.py:499-526).
  - So no V2 size can be above ×1, and ×1 is below the bridge ceiling (section 1).
- **Unit tests also pin the managed product:** test_identity_sizing.py:227-246, 0.5 × 0.75 = 0.375 passed to the engine.
