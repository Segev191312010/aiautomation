### LOW-1: the installed P1-B head is not in the commit table, so a P1-B run that records no decision is an "unknown" session and restarts "sessions since the last step" until the table is regenerated

- **Where:**
  - `size_history.table_version_for` (size_history.py:133-153) reads a run's `source_sha` (`git rev-parse HEAD` of the live checkout, `-dirty` stripped) only from `source_commits.py`. A commit cannot list itself (source_commits.py:33-37). 0217e10 is the only reachable commit that is not listed (my re-derivation below), and the real deploy head will be 0217e10 plus this review's docs/reviews commits, also unlisted.
  - `run_factor` (size_history.py:269-283) uses the T-8 sidecar records of a run when the run has any. It falls back to the sha only for a run with no record: a run that made no decision that day, or one whose sidecar was disabled by its first write (pipeline.py `_record_sizing`, the N15a MEDIUM-1 bound).
  - `identity_size_history` (size_history.py:366-404) turns such a run into an `unknown` session; `sessions_since_last_step` (size_history.py:336-351) stops counting at the first unknown session; `evaluate_identity` (promotion_proposals.py:344, 366) needs `MIN_SESSIONS_SINCE_STEP` = 10.
- **Evidence** (`probes/unlisted_head.py`, real functions): ORB_V2 runs 10-19 on 2608230 (no decisions: `derived_from_source_sha:v7b`, x0.25), 10-20 and 10-22 on 0217e10 with sidecar records, 10-21 on `0217e10…-dirty` with none. Result: sessions `derived, recorded, unknown, recorded`; `sessions_since_last_step(0.25) = 1`, `unknown_sources = ('0217e105d566',)`. After adding the prefix to `V7B_SIZED_COMMITS` (what the next regeneration does) the same history gives 4.
- **Failure scenario:** the owner installs P1-B on Sunday. On a later day ORB_V2 (or GAP_GO_V2) forms no setup and records no decision. Every night after, until `source_commits.py` is regenerated, that identity's nightly evidence counts its "sessions since the last step" only from after that day, and names `0217e105d566` (or the deploy head) under `unknown_sources`.
- **Why only LOW:**
  - It only delays an "up" proposal, and every "up" proposal is HELD anyway until v7c (`OPEN_RISK_TERM_DEPLOYED = False`, promotion_proposals.py:95; `MIN_SESSIONS = 20` also applies). A demotion does not look at it (promotion_proposals.py:369).
  - Every decision P1-B makes carries its own multiplier in the T-8 sidecar, so sizes and `trades_by_multiplier` are exact. Only a decision-less run, or a sidecar that failed at its first write, falls back to the sha.
  - It is recomputed from scratch every night, so one data-only regeneration that lists the deploy head heals all of history. Nothing reads it at order time.
- **Fix (owner's choice, both small, neither blocks the install):** after the install, regenerate `source_commits.py` so it lists the deploy head (a data-only, reviewed change). Or let `run_factor` take a run with no record and an unlisted sha whose commit is a descendant of a `V7B_SIZED` commit as `v7b`, but that needs git at runtime, which the module avoids on purpose. The first is the existing process; the docstring already states the limit.
