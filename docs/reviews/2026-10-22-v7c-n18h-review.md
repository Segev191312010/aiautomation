## 1. The process boundary against the bridge's real lines

Rule 7 now keys pending lines by `process = (line.run, connects[line.run])` (`session_check.py:1469-1493`):
- `line.run` is the section run, from `_blocks` (`:362`): a new supervisor banner, or a `bridge sha256=` line once the current block has started or is unsupervised.
- `connects` counts `PAPER bridge … connected` INFO lines within the run.

The lines the bridge actually writes:

| Line | Who writes it, and when | Rule 7 effect |
|---|---|---|
| `=== <at> supervisor starts bridge: … --date D` | `supervisor.start()` writes it to bridge.log before `create_subprocess_exec` (`supervisor.py:1447-1453`), once per child start, after the previous child exited | new run |
| `bridge sha256=<64>` | `main()`'s first line (`paper_bridge.py:4632`) | new run when not the first sha line of a supervised block |
| `PAPER bridge v7c connected (all accounts paper)…` | `_connected_session` (`:4595`), called once from `main()` (`:4662`); `_connect` is only called there (`:4587`), and `app.connect` only in `_connect` (`:4550`) | connect count 1 for the run |
| `day risk budget 3% …` rule line | `:4606`, after the connect line | `budget_runs` (per run, unchanged) |
| `v7c_budget_ok … (source=bot)` | `process_decision` (`:1836`), on the loop thread, inside `bridge.run()`, i.e. after the connect line | pending at (run, 1) |
| `v7c_budget_ok … (source=manual)` | `ManualDesk.buy` (`:3924`), on the loop thread; the desk is built after the connect line (`:4607-4610`) | pending at (run, 1) |

**Is there an in-process reconnect? No.**
- `main()` runs once per process (`sys.exit(main())`) and connects once.
- A lost API connection makes `interrupted()` log CRITICAL "TWS connection lost … Exit 75" (`:2917-2924`). The process ends with `bridge stopped (exit 75)`. The supervisor then starts a new child, which writes a new banner, sha and connect.
- The connect watchdog calls `os._exit(75)` before any connect line (`:4459-4466`).
- TWS codes 1100/1102/1300/2110 are TWS's own link to IBKR; the API socket stays up. They log as `TWS -1 1100 …` (CRITICAL) or `TWS -1 1102 …` (INFO), with no connect line. Rule 7 correctly does not treat them as a process start, because the process is the same.
- So within a process every budget line and every SENT sits at connect count 1. The connect count only adds a split when a run holds two processes whose second sha line is missing; the builder's `second-connect` test covers that case.

## 2. Can the boundary split a legitimate pair and FAIL a good day?

**Not on the bridge as built.**

- **Bot entries.** The budget line (`:1836`) and `submit()` run back to back on the loop thread. `submit()` logs SENT (`:1869`) after its three `placeOrder` calls.
  - If a stop or a disconnect intervenes, `submit()` returns with no SENT ("left unprocessed; the loop exits 75 and the restart re-evaluates it"). The new process runs `process_decision` again and logs its own line.
  - "Persist before transmission" means a stored bracket is never re-sent.
- **Owner buys.** `ManualDesk.buy` logs the budget line, then `place_entry`, then `MANUAL SENT … (order N) with its stop …` (`:3944`), all in one call.
  - After a restart the follow-up reads `(orders [...])` (`:4403`). `_MANUAL_BUY` does not match it, so a restart never shows a buy that has no line.
- **Lines that can fall between a budget line and its SENT** come from:
  - the reader thread, e.g. `order N: PreSubmitted …` INFO (`:1157`). This is realistic, because the parent transmits on the third `placeOrder`, before SENT is logged;
  - TWS error lines (`:1332`, `:1336`);
  - stderr tracebacks (the child's stderr is merged into the same file, `stderr=subprocess.STDOUT`).

  None of them is an INFO event that begins `PAPER bridge <v> connected`. `log()` writes each line in one locked write and flushes it (`:350-359`).
- **Log rotation** happens only between sessions (`supervisor._wait_until`: "never during a session, so a rotation never splits one"). A process therefore never spans two bridge.log files. This matters because blocks are cut per file.
- **The only overlap case** is two bridge processes writing at once, an incident in its own right. A FAIL there is the right outcome.
