```sql
CREATE TRIGGER autotrader_size_proposals_no_replace BEFORE INSERT ON autotrader_size_proposals
  WHEN EXISTS (SELECT 1 FROM autotrader_size_proposals WHERE proposal_id = NEW.proposal_id)
  BEGIN SELECT RAISE(ABORT, 'size proposals are append-only'); END;
CREATE TRIGGER autotrader_size_decisions_no_replace BEFORE INSERT ON autotrader_size_decisions
  WHEN EXISTS (SELECT 1 FROM autotrader_size_decisions WHERE proposal_id = NEW.proposal_id)
  BEGIN SELECT RAISE(ABORT, 'size decisions are append-only'); END;
CREATE TRIGGER autotrader_size_events_no_replace BEFORE INSERT ON autotrader_size_events
  WHEN EXISTS (SELECT 1 FROM autotrader_size_events WHERE id = NEW.id OR proposal_id = NEW.proposal_id)
  BEGIN SELECT RAISE(ABORT, 'size events are append-only'); END;
CREATE TRIGGER autotrader_size_evaluations_no_replace BEFORE INSERT ON autotrader_size_evaluations
  WHEN EXISTS (SELECT 1 FROM autotrader_size_evaluations
               WHERE id = NEW.id OR (identity = NEW.identity AND as_of = NEW.as_of))
  BEGIN SELECT RAISE(ABORT, 'size evaluations are append-only'); END;
```

## 5. Open questions 1-3

1. **Size CRITICALs do not reach the phone.**
   - Confirmed: notify_service forwards only `MANAGER_TRIPWIRES`, although it already tails every strategy child's `<name>.log`.
   - **Recommendation:** in P3-E, before L-sizes (not a P3-C blocker), add a `SIZE_TRIPWIRES` tuple:
     - `identity_size_store_unreadable`, `identity_size_above_ceiling`, `size_event_chain_broken`, `size_event_written_mid_session`, `size_read_before_session_start`;
     - `account_mode_without_ceiling`, `sendable_without_ceiling`, `identity_sizing_missing`.
   - Give it its own phone label ("size tripwire", not "AI day manager tripwire"), 30-minute dedupe per token, and a test built from real child log lines (LEARNED: fixtures copy the real log format).
   - This is LOW-7.
2. **A temporary read failure blocks the identity for the whole run.**
   - Both options are fail-closed, so either is acceptable for ES. My recommendation is to **keep None** for the deterministic causes (no ceiling, above ceiling, chain broken, v18 pending, checksum mismatch, row does not parse). These would fail again on restart, and a restart loop would only hit the restart cap.
   - For **`sqlite3.OperationalError` only** (busy, locked, I/O): retry inside the child, for example 3 tries 10 s apart (still before `actor.connect()`), then None with the CRITICAL.
   - Do not exit 75 for this: `test_only_the_schema_gate_can_exit_a_scheduled_child_with_75` reserves 75 for the schema gate. A new non-zero exit would interact with run resume, the lease TTL backoff and the restart cap for little gain. A WAL `mode=ro` reader with a 5 s busy timeout almost never sees a transient error.
   - The real gap is paging (question 1).
3. **Trusting the writer's `created_at`.**
   - Acceptable for P3-C, because no writer exists yet, but the trust is real:
     - the mid-session guard and the back-dating CHECK both read `created_at`;
     - a back-dated `created_at` makes a mid-session write look pre-session, so a restarted child would apply it;
     - a future-dated one is safe (ignored until the next session).
   - **Recommendation:**
     - P3-D and P3-E take `created_at` (and the decision `at`) from one `datetime.now(timezone.utc)` at write time, inside the writing transaction, with a test that pins it; N20 and the P3-E review verify this.
     - Do not add a `julianday('now')` trigger: it would tie every fixture to the wall clock.
   - Decide this before v18 is applied. Afterwards, any DB-side guard needs migration 19.
