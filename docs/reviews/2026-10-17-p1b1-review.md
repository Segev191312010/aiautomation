### LOW-1: the 16:15 take-over borrows a stale "paged" outage from a notifier that died mid-outage, so a new evening outage is not paged until 05:55

- **Where:**
  - `notify_service.py:486-506`: `notifier_gateway_outage` has no freshness check. `paged` is
    simply "the `BROKER_UNREACHABLE` alert key is present".
  - `overnight_watch.py:393-413` (`_take_over`, then `port.carry(known)`).
  - `gateway_watch.py:375`: `self._paged = True  # the phone has this outage already: no second page`.
- **Why the state can be stale:** the notifier rewrites `gateway_outage_since`/`kind` every cycle
  (`_sync_gateway_outage`, :2455) and pops the alert key only at a recovery event (:2575). If the
  notifier stops running in the middle of an announced outage (crash loop and suspension, a hang,
  a kill), its per-date file keeps "paged outage since T" for the rest of the day, whatever the
  port does afterwards.
- **Evidence (reviewer probe, `probes/test_probe_n15c_watch.py`, run on the real
  `OvernightWatch` and `notifier_port_outage` with the test suite's fake clock and port):**
  - Setup: the notifier paged a 09:00 outage and its file kept it. The port reopened at 10:30 with
    nobody watching, and closed again at 15:30.
  - The watch sent **nothing** from 16:10 to 18:25.
  - The same day without the borrowed evidence (the pre-commit behaviour) sends
    `⛔ IB Gateway closed since before 16:15 ET … log in to IB Gateway` on schedule.
  - The next page is the 05:55 lead, and it says "closed since 09:00".
- **Failure scenario:** the notifier is suspended at 10:00 (the watch now forwards that page,
  N15b L-3) while a Gateway outage is open. The outage clears at 10:30, and the Gateway logs off
  again at 15:30. The 16:20-17:30 recorder run is lost with no evening page, and the owner, who is
  plausibly awake at 23:20 Israel, never hears of it.
- **Severity:** no order impact (the bridge fails closed on a closed port), and it needs two
  faults. Hence LOW.
- **Same class, text only:** a `telegram` restart whose saved outage (`port_outage_*`) is from an
  outage that ended while the child was down. A Friday 16:45 paged outage, child down, port
  closed again on Sunday: Monday's 05:55 and 07:40 pages say "closed since Fri 16:45". Both pages
  are still sent.
- **Fix (small):** carry the notifier's outage only when its state file was written near the end
  of its window. For example, use the file's mtime ≥ `NOTIFIER_FINISH`, or stamp
  `gateway_outage_checked_at` each cycle and require it within ~5 min of 16:15. Otherwise ignore
  it, or carry it with `paged=False`. Add the probe above as a test.

### 2. Sidecar (`pipeline._record_sizing`, `decision_sizing.py`)

- **Decisions stay byte-identical.** The golden MOMO and ORB digests hold, and BF B's quantity is
  931, with a hung recorder, a FIFO, every write failing, the first only, or a non-async writer
  (builder tests). The diff touches only the sidecar call.
- **Timeout and disable:**
  - A hung default write times out (`TimeoutError` is an `OSError` on 3.11) and the sidecar is
    disabled for that pipeline instance. Each run gets its own copy via `with_decision_recorder`
    (persistence.py:316), so the disable really is per run.
  - Probe: a write that lands 0.4 s after a 0.1 s deadline is one complete line. The reader shows
    1 record and no unreadable entries; the next decision is not attempted and waits 0.000 s.
  - The thread writes one short line with a loop of `os.write` on an `O_APPEND` fd. A timeout
    never interrupts the thread, so the only partial line possible is from an `ENOSPC` or a
    SIGKILL mid-write (pre-existing). The reader then skips that one line as
    `unreadable file:line` and never guesses.
- **Daemon thread:**
  - The process exits in 0.30 s with a write parked forever. The old `asyncio.to_thread` hung past
    8 s.
  - 150 consecutive real writes: the thread count stayed at baseline (1), all 150 lines landed,
    and none was unreadable.
  - The recorder awaits the thread's future, so a line is on disk before the next candidate
    unless the deadline cut the wait. Then that one line may be lost at exit, and the sidecar is
    off for the run anyway.
  - The promoter on a missing line: `effective_multiplier_for` returns `unknown` with value None
    ("source 'ff45ec8abb37' is not in the commit table"). A run with no lines gives
    `run_factor` = `unknown`, and `sessions_since_last_step` stops counting at an unknown session
    (size_history.py:320-335). This is conservative, never a guessed multiplier.
- **Stops are never swallowed.** A task cancel at −30, −3, −1, 0, +1, +3 and +30 ms around the
  deadline always ended with the task cancelled. Before the deadline, `CancelledError` came out of
  the pipeline; after it, the cancel was delivered at the runner's next await. This is 3.11.15's
  `asyncio.timeout` uncancel accounting, the gh-86296 lesson.
- **`lstat`/`S_ISREG` and the open flags:** a FIFO, a directory or a symlink is refused before any
  open (builder test with an `os.open` spy). `O_NONBLOCK` makes a racing FIFO fail with ENXIO,
  `O_NOFOLLOW` makes a racing symlink fail with ELOOP, and `fstat` re-checks.
